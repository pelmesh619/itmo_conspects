## Лекция 6. Удаленный репозиторий Git

Удаленный репозиторий (Remote repository) - это репозиторий проекта, который размещен на сервере или облачной платформе. Удаленный git-репозиторий выполняет несколько задач:

* Удаленный репозиторий позволяет нескольким разработчикам обмениваться изменениями, не находясь за одним компьютером
* Код хранится не только локально, но и на внешнем сервере, тем самым храня резервную копию
* Репозиторий выступает централизованной точкой сборки проекта

У одного проекта может быть несколько удаленных репозиториев. Удаленные репозитории могут размещаться на публичных облачных платформах или на собственных серверах компании. Примеры платформ для удаленных репозиториев:

* GitHub - крупнейший хостинг репозиториев, принадлежащий Microsoft, хорошо подходит для публичных репозиториев
* GitLab - независимая платформа
* Bitbucket - платформа от Atlassian, имеющая интеграция с другими сервисами (Jira, Confluence и так далее)
* GitVerse - платформа от Сбера

Также существуют платформы, которые можно установить на собственном сервере, например, GitLab Community Edition

С точки зрения базовых возможностей Git все эти платформы предоставляют схожий функционал, и различия обычно состоят в экосистеме, инструментах CI/CD и модели распространения

---

Подключение сводится к тому, чтобы связать локальный репозиторий с URL-адресом удалённого. Git поддерживает два основных протокола для этого:

* Протокол HTTPS

    Подключение по HTTPS является простым способом. Клонированию доступно с помощью команды:

    ```bash
    git clone https://github.com/username/repo.git
    ```

    где `https://github.com/username/repo.git` - URL-ссылка на репозиторий (`repo` - имя репозитория, `username` - имя владельца)

    Для клонирования публичных репозиториев не требуется авторизация, а для записи своих коммитов и клонирования приватных репозиториев требуется. Обычно авторизация осуществляется в виде логина и пароля либо через токен доступа, который можно сгенерировать на сайте платформы

* Протокол SSH

    Для подключения через протокол SSH нужно сгенерировать два ключа (публичный и приватный), которые можно сгенерировать командой:

    ```bash
    ssh-keygen -t ed25519 -C "your_email@example.com" -f ~/.ssh/github_key
    ```

    Утилита `ssh-keygen` принимает электронную почту и имя файла будущего ключа и спрашивает парольную фразу, которую можно оставить пустой. На основе этих данных утилита по алгоритму Ed25519 генерирует два файла: приватный ключ `~/.ssh/github_key` и публичный ключ `~/.ssh/github_key.pub`. Парольная фраза служит для шифрования приватного ключа на компьютере. Приватным ключом `~/.ssh/github_key` нельзя делиться с кем-либо, публичный же ключ `~/.ssh/github_key.pub` добавляется в настройках учетной записи платформы
    
    Далее можно склонировать репозиторий:

    ```bash
    git clone git@github.com:username/repo.git
    ```

    Здесь `git` - это имя пользователя в операционной системе сервера (почти всегда это `git`), `github.com` - имя хоста (здесь может быть IP-адрес, если Git-сервер приватный)

    Такой метод, как правило, является более безопасным, чем HTTPS

Вместо клонирования существующего удаленного репозитория можно связать локальный репозиторий с новым пустым репозиторием на сервере. Для этого нужно:

1. Создать пустой репозиторий на платформе и скопировать URL репозитория
2. Далее добавить ссылку на удаленный репозиторий в локальном командой:

    ```bash
    git remote add origin git@github.com:user/repo.git
    ```

    Здесь `origin` - общепринятое имя для удаленного репозитория, а `git@github.com:user/repo.git` - ссылка на репозиторий

3. После этого отправить локальные коммиты на сервер командой:

    ```bash
    git push --set-upstream origin main
    ```

    Флаг `--set-upstream` (или `u`) связывает текущую ветку (в данном пример `main`) с веткой `main` на удаленном репозитории `origin`. Для этого `git` локально создает ветку `origin/main`. После такого связывания можно использовать просто команду `git push`

---

Другие команды для работы с удалённым репозиторием:

* `git remote -v` - список всех настроенных удаленных репозиториев и их ссылки
* `git push <remote> <branch>` - отправка коммитов на конкретный удалённый репозиторий
* `git pull <remote> <branch>` - сбор коммитов из удалённого репозитория в ветку `origin/main` и слияние их с локальной веткой `main`
* `git fetch <remote>` - только сбор коммитов из удалённого репозитория в ветку `origin/main`. `git fetch` позволяет сначала просмотреть изменения, а затем решить, какие из них слить в локальную ветку
